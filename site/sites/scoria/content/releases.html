Releases

A v* tag builds the scoria binary on both forges and publishes one archive per platform with a SHA256SUMS file over all of them. Every release since 0.1.0 is listed here, newest first, and the three download addresses below always point at the newest one.

Linux x86-64 Windows x86-64 macOS Apple silicon Platform notes

Those addresses are versionless on purpose: they resolve to whatever the newest release is, so a link to them never goes stale. Each release also carries the same three archives named for their tag, which is what you want in a downloads folder you will come back to.

0.5.0 — the Writer gate passes

Released 9 November 2026. The gate for the writing phase was a sentence about a person: a vault round-trips byte-identical after a week of mixed use in both apps. A real vault spent seven days being edited in Scoria and in Obsidian in turn, and every byte that moved was a person's edit in one of the two; the comparison found and fixed what it was there to find.

The gate

Seven days, two apps, one vault

Notes, renames, moves, tables, suggesters, templates, daily notes, both canvases, the editing and fold commands, splits, bookmarks and settings — each day's half in Scoria over its control socket, the other half by hand in Obsidian 1.15.0, the vault diffed against a baseline after each. Obsidian kept every byte Scoria wrote to bookmarks.json and to the canvases, so those writers are fixed points of its own.

What it fixed

Found by the comparison

alwaysUpdateLinks defaulting on; types.json unseeded; a dragged canvas card not raised to the end; Mod+B taking the list marker; the numbered toggle counting straight down where Obsidian counts per depth; a fold over the scroll anchor; Settings tabs sharing a scroll offset; and serde_json's float parser dropping an ulp on a dock width, which float_roundtrip now keeps.

Bookmarks

The pane, against 1.15.0

Files, folders, headings, blocks, searches, graphs and groups, each with Obsidian's icon, menu and rename on the row; drag a note in from Files and it is bookmarked at the drop; the view header's bookmark action; and the writer that Obsidian re-read and kept byte for byte.

Tables

Handles, bars and a padded entry

Live Preview tables grew Obsidian's row and column handles that drag to reorder, the "+" bars that append a row or a column, keys that leave a table the way Obsidian's do, and the re-pad on the first click into a cell. The inline title is a field, and arrow keys enter a table from the text around it.

Files

Renames on the row

A file tree row renames in place rather than in a dialog, new notes and folders are named on their row, and the Update links prompt has Obsidian's three buttons — Always update, Just once, Do not update — with none of them accented, as none is in Obsidian.

Commands

Change theme, and the probes

theme:switch opens its suggester — Default with an Active flair, then the installed themes — so hotkeys.json's binding reaches it. The week's open questions were settled by a probe against 1.15.0 and recorded in the specification beside the behaviour each one extends.

Checking what you downloaded

Three independent checks, in increasing order of what they prove. None of them needs an account, and the first one is the one worth doing every time.

SHA256SUMS lists both names of every archive, so the check works whether you took the versionless address or the tagged one. On macOS the first command is shasum -a 256 -c --ignore-missing SHA256SUMS, and on Windows Get-FileHash prints a hash to compare by eye.

The signing key is 69BF AA44 7DAC E6C3 EF02 6CBA 4EA6 7A61 88DA 92BD (ragtux <ragtux@outlook.com>), which gpg --keyserver keys.openpgp.org --recv-keys 4EA67A6188DA92BD fetches; each release's notes repeat the fingerprint that signed it. A release published without the key available says so in its notes rather than carrying an unsigned .asc.

How a release is made

Two forges

The same tag, pushed twice

A v* tag on GitHub builds all three platforms; the same tag on git.ragtux.com builds the Linux archive, because the homelab runner has only a Linux container. Same commit, same Cargo.lock, same binary.

Gate

The tag has to match the manifest

The first job compares the tag against the workspace version and fails the release before a build slot is spent if they disagree — the archives are named from the tag and the binary reports the manifest, so a mismatch would ship a lie.

Reproducible

Built --locked

Cargo.lock pins libc and the exact GPUI revision on purpose, and the release job builds with --locked so the lockfile decides. Building the tag yourself gives you the same dependency graph CI used.
